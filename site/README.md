# 방화 FC 홈페이지

`index.html` 한 장짜리 정적 홈페이지다. 빌드가 없다 — 파일을 브라우저로 열면 그대로 뜬다.

레인보우식스 관리자(`data2102/rainbow` 의 `public/index.html`)와 같은 골격을 쓴다.
헤더 카드 → 왼쪽 세로 메뉴 → 패널 카드, [여백 디자인 시스템](https://github.com/data2102/design-system)
토큰. **액션색만 파랑에서 빨강으로 바꿨다.**

## 화면

| 메뉴 | 무엇 |
|---|---|
| 연혁 | 창단부터 지금까지를 세로 타임라인으로 |
| 회원 | 이름·연령대·포지션·가입·연락처·직책. 이름/포지션 찾기와 연령대 거르기 |
| 회비 | 달을 골라 완납·미납. 연납은 금액을 12로 나누지 않고 그 달을 완납으로 본다 |
| 찬조 | 올해 합계와 건별 내역(받은 날·사유·쓴 곳) |
| 정관 | 6개 장 20개 조문. 위 칩을 누르면 그 장으로 간다 |
| 대회일정 | 다음 경기 D-day, 올해 전적, 예정·지난 경기 |

## 명단은 저장소에 없다

**실제 명단은 `site/roster.local.js` 에 있고 이 파일은 `.gitignore` 에 있다.**
실명·전화번호·생년월일이 들어 있고 저장소는 공개다 —
`scripts/import-roster.mjs` 가 만드는 SQL 과 같은 규칙이다.

`index.html` 이 그 파일을 먼저 읽는다(`window.BHFC_ROSTER`). 없으면 아래 데모
명단으로 뜨니까, 저장소만 받은 사람도 화면은 그대로 볼 수 있다.

```js
window.BHFC_ROSTER = [
  { name: '홍길동', role: '총무', birth: '1988-08-01', phone: '010-0000-0000' },
];
```

칸은 성명·직책·생년월일·전화번호 넷이다. **연령대는 생년월일에서 저절로 나오고**,
직책이 비어 있으면 일반 회원이다. 이 명단으로 들어온 분은 회비 탭에서 `기록 없음`
으로 서고 완납·미납 수에서 빠진다 — 없는 기록을 지어내지 않는다.

## 로그인

이름 · 전화번호 · 비밀번호 셋을 받고, **비밀번호는 전화번호 뒤 4자리**다.
다만 그 규칙을 화면에 적지는 않는다.

**지금은 화면 안에서만 맞춰 본다.** 명단이 브라우저에 그대로 실려 있으니 이대로는
잠금이 아니라 문패에 가깝다. 실제로 쓰려면 `doLogin()` 을 서버 요청 하나로 바꾸고,
전화번호 뒤 4자리는 **첫 로그인 때만 쓰는 초기 비밀번호**로 두고 바꾸게 해야 한다 —
번호를 아는 사람이 곧 비밀번호를 아는 사람이기 때문이다.

## 자료

`MEMBERS` · `HISTORY` · `SUPPORT` · `SCHEDULE` · `RULES` 다섯 덩어리가 파일 안에 있다.
서버에 붙일 때는 이 다섯을 `fetch` 로 바꾸기만 하면 되고, 그리는 쪽은 손댈 데가 없다.

**이름은 가운데를 가렸고(김\*만) 전화번호도 실제 번호가 아니다.** 저장소가 공개라
실명을 두지 않는다 — 이 저장소의 다른 데이터와 같은 규칙이다.

## 확인

```bash
npx serve site -l 4173   # 브라우저에서 확인
```

Expo 앱(`src/`)과는 별개다. GitHub Pages 배포(`deploy-web.yml`)는 Expo 번들만 올리므로
이 폴더는 아직 어디에도 배포되지 않는다.
