# 방화 FC 홈페이지

`index.html` 한 장짜리 정적 홈페이지다. 빌드가 없다 — 파일을 브라우저로 열면 그대로 뜬다.

레인보우식스 관리자(`data2102/rainbow` 의 `public/index.html`)와 같은 골격을 쓴다.
헤더 카드 → 왼쪽 세로 메뉴 → 패널 카드, [여백 디자인 시스템](https://github.com/data2102/design-system)
토큰. **액션색만 파랑에서 빨강으로 바꿨다.**

## 화면

## 로그인 화면만 문장(crest)의 세계다

`crest.png` 는 팀 문장이다(원본 1024px 을 투명한 테두리만큼 잘라 512px 로 줄였다).
로그인 화면은 문장에 맞춰 **남색 바탕에 금색**이고, 문을 지나면 원래의 빨강 화면이다.

색 토큰을 `#gate` **안에서만** 다시 정하기 때문에 이렇게 된다 — 바깥 `:root` 토큰은
건드리지 않는다. 로그인 화면은 `position:fixed; inset:0` 으로 화면을 꽉 채운다.
판이 아니라 문이라서다.

화면이 낮으면(가로로 누운 폰) 문장을 96px 로 줄이고 여백을 좁혀 로그인 단추를 위로
끌어올린다.

## 명단은 저장소에 없다

**실제 명단은 `site/roster.local.js` 에 있고 이 파일은 `.gitignore` 에 있다.**
실명·전화번호·생년월일이 들어 있고 저장소는 공개다 —
`scripts/import-roster.mjs` 가 만드는 SQL 과 같은 규칙이다.

`index.html` 이 그 파일을 먼저 읽는다(`window.BHFC_ROSTER`). 없으면 아래 데모
명단으로 뜨니까, 저장소만 받은 사람도 화면은 그대로 볼 수 있다.

```js
window.BHFC_ROSTER = [
  { name: '홍길동', role: '총무', birth: '1988-08-01', phone: '010-0000-0000' },
];
```

칸은 성명·직책·생년월일·전화번호 넷이다. **연령대는 생년월일에서 저절로 나오고**,
직책이 비어 있으면 일반 회원이다. 이 명단으로 들어온 분은 회비 탭에서 `기록 없음`
으로 서고 완납·미납 수에서 빠진다 — 없는 기록을 지어내지 않는다.

## 권한

`ADMIN_ROLES = ['마스터', '총무', '부총무', '감독']`. 이 셋만 관리자 메뉴가 보이고,
명단을 고치거나 회비를 체크할 수 있다. 회비 탭은 **모두에게 보기 전용**이다.

숨기는 것으로 끝내지 않는다 — `openTab()` 이 관리자 탭을 열 때 권한을 다시 보고,
체크·비고·명단을 고치는 손잡이도 각자 `isAdmin(me)` 를 확인한다. 저장해 둔 탭으로
들어오는 길이 있어서 화면을 감추는 것만으로는 모자란다.

**마지막 관리자는 내려놓을 수 없다.** 관리자를 전부 없애면 이 기기에서는 아무도
명단을 못 고친다 — 직책을 바꾸는 것도 지우는 것도 막는다.

## 명단 고치기는 파일을 덮지 않는다

관리자가 고친 것은 `roster.local.js` 를 덮지 않고 **그 위에 얹힌다**
(`localStorage`, `bhfc-roster-edit` — 지운 사람 · 고친 칸 · 새로 넣은 사람).
덮어 버리면 명단 파일을 나중에 고쳐도 이 기기에서는 옛 명단이 계속 뜬다.
"고친 것 되돌리기"를 누르면 파일 그대로로 돌아간다.

명단 차례는 `ageKey()` 가 정한다 — **나이 많은 분이 위**다. 생년월일이 있으면 그 해를
쓰고, 연령대만 아는 분은 그 띠의 한가운데로 치고, 둘 다 모르면 맨 아래에 둔다
(모르는 것을 60대 위에 세울 수는 없다). 번호(`no`)는 이 차례를 매긴 값이라
집행부·회원·관리자 세 표가 같은 순서를 본다.

사람을 잡는 열쇠는 `uid`(처음 들어온 전화번호, 번호가 없으면 명단 파일이 직접 준다)다. 전화번호를 고치는 순간
번호로 잡던 회비와 로그인이 남의 줄로 간다.

## 회비는 "체크"가 아니라 "받은 금액"이다

`paid` 는 달 번호 배열이 아니라 **달마다 받은 금액**을 담는다
(`{ '1': 20000, '3': 35000 }`). 늘 2만원만 들어오지 않아서다 — 6만원을 한 번에
주고 가기도 하고, 3만 5천원처럼 딱 떨어지지 않기도 한다.

- **칸을 누를 때마다 2만원씩 오른다.** 2만 → 4만 → 6만 → 8만 → 10만 → 0.
  흔한 쪽을 한 번에 끝내고, 잘못 눌러도 몇 번만 더 누르면 지워진다.
- **받은 금액으로** 모드에서는 칸이 숫자 입력칸이 된다. 딱 떨어지지 않는 금액과
  한 번에 지우기는 이쪽이 맡는다.
- 2만원이 아닌 달은 칸에 `3.5만` 처럼 금액이 뜬다. **2만원에 모자란 달은
  노란 칸이고 미납으로 센다**(`fullPaid`) — 냈다고 다 채운 것은 아니다.

예전에 `paid: [1,2,3]` 으로 저장된 줄은 읽을 때 2만원씩 낸 것으로 옮긴다.

## 연선납은 나누지 않는다

한 해분을 미리 내면 두 달치를 깎아 **20만원**이다. 이 값을 12로 나눠 달에 붙이면
매달 조금씩 모자란 것처럼 보여서 **연선납한 분이 열두 달 내내 미납으로 뜬다.**
그래서 `paidWon()` 이 연선납이면 `DUES_ANNUAL` 을 그대로 돌려주고,
`hasPaid()` 는 연선납이면 어느 달이든 참이다.

달칸을 하나씩 켜 두지도 않는다 — **연선납을 풀면 원래 내던 달이 살아 있어야 한다.**
`annual` 은 `paid` 배열과 따로 있는 칸이다.

연선납과 면제는 같이 설 수 없다(한 해치를 냈는데 면제일 수는 없다).
하나를 켜면 다른 하나가 내려간다.

## 회비 체크는 어디에 남나

**지금은 이 브라우저에만 남는다**(`localStorage`, `bhfc-dues-<연도>`). 서버가 없어서
총무가 켠 표가 다른 분 화면에는 안 보인다. 붙일 때는 `loadDues()` 와 `saveDues()`
**둘만** 요청으로 바꾸면 되고, 그리는 쪽은 손댈 데가 없다.

사람은 `uid` 로 잡는다. 번호(`no`)로 잡으면 명단이 늘 때 줄이 밀려서
남의 줄에 체크가 붙는다. 비고(`note`)도 같은 자리에 담긴다.

## 로그인

이름 · 전화번호 · 비밀번호 셋을 받고, **비밀번호는 전화번호 뒤 4자리**다.
다만 그 규칙을 화면에 적지는 않는다.

**지금은 화면 안에서만 맞춰 본다.** 명단이 브라우저에 그대로 실려 있으니 이대로는
잠금이 아니라 문패에 가깝다. 실제로 쓰려면 `doLogin()` 을 서버 요청 하나로 바꾸고,
전화번호 뒤 4자리는 **첫 로그인 때만 쓰는 초기 비밀번호**로 두고 바꾸게 해야 한다 —
번호를 아는 사람이 곧 비밀번호를 아는 사람이기 때문이다.

## 자료

`MEMBERS` · `HISTORY` · `SUPPORT` · `SCHEDULE` · `RULES` 다섯 덩어리가 파일 안에 있다.
서버에 붙일 때는 이 다섯을 `fetch` 로 바꾸기만 하면 되고, 그리는 쪽은 손댈 데가 없다.

**이름은 가운데를 가렸고(김\*만) 전화번호도 실제 번호가 아니다.** 저장소가 공개라
실명을 두지 않는다 — 이 저장소의 다른 데이터와 같은 규칙이다.
